NBS BIM Object Standard — naming guide

From NBS BIM Object Standard Version 2.2 (July 2023), Section 5 Metadata requirements. Collapsed by default.

5.1.2 Composition rules
  • Names use alphanumeric characters only (a–z, A–Z, 0–9), max 75 characters.
  • Fields separated by underscore _; dash - allowed inside phrases.
  • Each field is PascalCase (capitalised words, no spaces).
  • No spaces or other punctuation.

5.2 File & BIM object naming

NBS arrangement:

<Originator>_<Source>_<Type>_<Subtype/Product code>_<Differentiator>

Differentiator is optional in NBS. Atana omits it from the family name so type catalogues stay clean; sizes live in the Revit type name.

Classification & IFC (OpenBIM)
  • Category → Uniclass Ss (systems) — what system the family belongs to.
  • Material → Uniclass Ma or Pr — material constitution.
  • Object → Uniclass Pr — product definition; name derived as reverse camelCase from Pr title keywords.
  • IFC4 — Ifc*Type enums for export / model checking (e.g. IfcBoilerType.WATER).
  • PyRevit can write Ss / Ma / Pr / IFC back to family shared parameters from this naming.
Task teams & Object lists
  • Object dropdown is filtered by task team (AR, ME, ST, EE, …).
  • Lists are curated generic design families for Atana enablement — not full manufacturer catalogues.
  • Manufacturer content belongs in Source, not in Object.
  • Use Export data Excel to edit lists; Import data Excel to update the in-session backend (and download updated JSON).
  • Use Export task team → FORMA template to produce an ACC/FORMA naming-standard workbook for the selected team.
Abbreviations (NBS 5.1.4)

Where platforms limit filename length, values may be abbreviated: max 7 characters, uppercase, no full stops or spaces. The same abbreviation is used for singular and plural.
